# Ассемблер и интерпретатор УВМ (вариант 5)

Ассемблер и интерпретатор для учебной виртуальной машины (УВМ) с одним регистром-аккумулятором.
Проект написан на C++23, собирается через CMake и работает на Linux и Windows.

Структура:

| Каталог        | Содержимое                                                       |
|----------------|------------------------------------------------------------------|
| `src/common`   | библиотека `common`: описание команд, кодирование и декодирование |
| `src/asm`      | библиотека `assembler` и программа `asm`                         |
| `src/vm`       | библиотека `interpreter` и программа `vm`                        |
| `tests`        | модульные тесты (GoogleTest)                                     |
| `examples`     | примеры программ на языке ассемблера                             |

## Спецификация УВМ

Каждая команда занимает 5 байт, байты записываются в порядке little-endian.
Поле A (биты 0–3) — код операции, поле B — аргумент.

| Мнемоника | A | Поле B             | Действие                         |
|-----------|---|--------------------|----------------------------------|
| `LOAD`    | 7 | биты 4–32, константа | `acc = B`                       |
| `READ`    | 6 | биты 4–27, адрес   | `acc = mem[B]`                   |
| `WRITE`   | 9 | биты 4–27, адрес   | `mem[B] = acc`                   |
| `MIN`     | 4 | биты 4–27, адрес   | `acc = min(acc, mem[B])`         |

Допущения, не указанные в спецификации:

- константы и ячейки памяти беззнаковые 32-битные, `min` сравнивает их как беззнаковые;
- память данных содержит 65536 ячеек и при запуске заполнена нулями; обращение за её пределы — ошибка;
- память команд и память данных разделены: программа не может читать или изменять свой код.

## Язык ассемблера

Одна команда на строке: мнемоника и один аргумент.

```asm
; комментарий до конца строки
LOAD 143      ; acc = 143
MIN 0         ; acc = min(acc, mem[0])
WRITE 0       ; mem[0] = acc
READ 0x1F     ; аргумент можно записать в шестнадцатеричном виде
```

- мнемоники не зависят от регистра (`load` = `LOAD`);
- аргумент — десятичное число или число с префиксом `0x`;
- пустые строки, пробелы и табуляции игнорируются;
- принимаются окончания строк LF и CRLF, а также UTF-8 BOM в начале файла;
- константа `LOAD` должна помещаться в 29 бит (не больше 536870911), адрес — в 24 бита (не больше 16777215).

При ошибке ассемблер печатает номер строки и причину и завершается с кодом 1:

```text
prog.asm: line 2: unknown mnemonic 'FOO'
```

## Сборка

Нужны CMake 3.28+ и компилятор с поддержкой C++23 (GCC 14+, Clang 18+, MSVC 2022).
CLI11 и GoogleTest скачиваются автоматически при конфигурации.

```sh
cmake -S . -B build
cmake --build build
```

Программы `asm` и `vm` появляются в `build/bin`.

## Запуск

### Ассемблер

```sh
asm -c <исходный файл> -r <двоичный файл> [-t]
```

| Опция          | Описание                                                  |
|----------------|-----------------------------------------------------------|
| `-c, --code`   | путь к исходному файлу на языке ассемблера                |
| `-r, --result` | путь к создаваемому двоичному файлу                       |
| `-t, --test`   | режим тестирования: вывести байты каждой команды          |

Ассемблер всегда выводит размер двоичного файла в байтах.

### Интерпретатор

```sh
vm -p <двоичный файл> -d <файл дампа> -r <первый адрес> <последний адрес>
```

| Опция           | Описание                                                      |
|-----------------|---------------------------------------------------------------|
| `-p, --program` | путь к двоичному файлу программы                              |
| `-d, --dump`    | путь к создаваемому XML-файлу с дампом памяти данных          |
| `-r, --range`   | первый и последний адрес памяти для дампа (включительно)      |

Формат дампа:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<memory>
  <cell address="0">10</cell>
  <cell address="1">143</cell>
</memory>
```

### Скрипты

- `run.sh` / `run.bat` — собирает проект, ассемблирует программу в режиме тестирования, выполняет её
  и печатает дамп. Аргументы: исходный файл, первый и последний адрес
  (по умолчанию `examples/vector_min_1.asm 0 4`). Результаты сохраняются в `out/`.
- `runtests.sh` / `runtests.bat` — собирает проект и запускает тесты.

```sh
./run.sh examples/copy_array.asm 0 14
./runtests.sh
```

## Примеры

| Файл                  | Что делает                                                        |
|-----------------------|-------------------------------------------------------------------|
| `spec.asm`            | тестовые команды из спецификации                                  |
| `copy_array.asm`      | заполняет ячейки 0–4 и копирует их в ячейки 10–14                 |
| `min.asm`             | `mem[2] = min(mem[0], mem[1])`, `mem[3] = min(mem[1], mem[0])`    |
| `vector_min_1..3.asm` | тестовая задача: `v[i] = min(v[i], 143)` для вектора длины 5 в ячейках 0–4 |

Ассемблирование `spec.asm` в режиме тестирования даёт байты из спецификации:

```text
$ build/bin/asm -c examples/spec.asm -r out/spec.bin -t
0x87, 0x3C, 0x00, 0x00, 0x00
0x56, 0x15, 0x00, 0x00, 0x00
0xA9, 0x22, 0x00, 0x00, 0x00
0xA4, 0x26, 0x00, 0x00, 0x00
Binary size: 20 bytes
```

Результаты тестовой задачи (ячейки 0–4):

| Файл               | Исходный вектор                | Результат                |
|--------------------|--------------------------------|--------------------------|
| `vector_min_1.asm` | 10, 200, 143, 0, 1000          | 10, 143, 143, 0, 143     |
| `vector_min_2.asm` | 500, 400, 300, 200, 100        | 143, 143, 143, 143, 100  |
| `vector_min_3.asm` | 142, 144, 143, 0, 536870911    | 142, 143, 143, 0, 143    |

## Тесты

```sh
ctest --test-dir build --output-on-failure
```

Тесты проверяют:

- кодирование и декодирование тестовых команд из спецификации, граничные значения аргументов
  и отказ при неверном коде операции или лишних битах;
- разбор языка ассемблера: комментарии, CRLF, BOM, шестнадцатеричные числа, ошибки с номерами строк,
  совпадение байтов `spec.asm` со спецификацией;
- выполнение каждой команды, ошибки интерпретатора (обрезанная программа, неверная команда,
  адрес вне памяти), примеры из `examples` и формат XML-дампа.
